# Localisation (i18n)

The kiosk runs **one locale per terminal**, chosen at build time by the
country pack (`country.pack` in `config.yaml`). There is no locale routing,
no negotiation and no translation library — the layer is a message catalog
per pack and a `t()` helper (`frontend/src/lib/i18n.ts`) that works
identically in client components and API routes, because the flow engine
speaks the same instructions the screens show. The one runtime exception is
the chat kiosk's **spoken-language detection** (below), which lets the
conversation — not the UI chrome — follow the language a citizen speaks.

## Changing the entire UI language

The whole kiosk — screens, flow instructions, prompts, speech — speaks the
language its country pack was written in, baked at build time. To change it:

1. **Translate (or pick) a country pack.** The pack owns every localised
   surface: the message catalog (`messages.ts`), the STT vocabulary and
   repair examples (`speech.ts`), the NLU keyword tables (`nlu.ts`), the
   prompt variables — including `language_instruction`, which a non-English
   pack MUST set (e.g. `"\nAlways reply in Vietnamese."`) or the assistant
   answers in English — and the whole `services/` tree with its labels,
   questions and step copy. The `add-country-pack` skill and
   [country-packs.md](country-packs.md) carry the full checklist.
2. **Set the config keys** in `config.yaml`: `country.pack`,
   `locale.language` and the other `locale.*` formats, `voice.stt.language`
   for the recognizer, and a `voice.tts.voice` that can actually speak the
   language (see the voice inventory in
   [configuration.md](configuration.md#spoken-languages-chat-mode)).
3. **Rebuild.** `country.pack` and `locale.*` are `NEXT_PUBLIC_*` values
   inlined by `next build` — a production build or packaged app must be
   rebuilt to change them.

Strings not yet extracted into the catalog (the generic shell copy — see
the cut-line below) ship in English; translating everything means extending
the catalog first.

## Spoken-language detection (chat mode)

Set `voice.languages` in config.yaml (mapping language code → TTS voice) to
let the chat kiosk follow the language a citizen speaks without any control
on screen. Per spoken turn:

1. The clip is recognized with the session's current language as the
   Whisper hint, then the transcript is language-classified by the LLM
   against the configured set (`detect-language` prompt). Only configured
   languages are ever adopted — anything else keeps the session language.
2. On a switch, the clip is recognized once more with the detected hint
   (Whisper biases its output toward the hinted language, so the first pass
   of a switched utterance is the worse of the two), and the session
   language follows — it becomes the next turns' STT hint and rides on chat
   turns as message metadata.
3. The conversational prompts get a per-turn
   `{{language_instruction}}` — `Always reply in <language>.` — so the LLM
   replies (and the live captions, which just render the reply) follow the
   citizen. For the pack's own language the pack's `language_instruction`
   stays in charge.
4. Narration picks the voice configured for the language. Flow turns — the
   step-by-step `say`/ask text, which is pack copy whatever the citizen
   spoke — keep the default voice; only free LLM replies switch
   (`narrationLanguage` in `use-chat-voice.ts`).

Every session starts back in the pack's language. Detection degrades to a
no-op whenever the LLM is mocked or unreachable.

What deliberately does **not** follow the citizen: the `t()` catalog and
all shell copy, the flow engine's instructions and buttons, typed-only
turns (no detection runs on the keyboard path — the composer keeps the
session language a spoken turn established), and the NLU keyword fallbacks,
which stay tuned to the pack. Routing free text in a detected second
language rides on the LLM alone. Known rough edges: the transcript-repair
vocabulary pass still runs (proper-noun aliases are language-neutral) but
the LLM repair step is skipped outside the pack's language; the live-caption
splitter is Latin-punctuation-based and degrades for scriptio-continua
scripts; and a first utterance in a distant-script language can be garbled
badly enough by the wrong hint that the detector never sees it — the second
utterance usually lands once the citizen persists.

## The cut-line: what goes through `t()`

Deliberately not every string. The catalog holds only what a country pack
must own — text that names the country's documents, agencies or procedures:

- the ID-reader instructions (`src/lib/id-reader.ts` — they name the MyKad),
- card-reader failure copy (`api/_lib/nfc.ts`),
- identity-document labels and the reader step card
  (`services/shared/steps/identity.tsx`, `flows/engine.ts`,
  `components/chat/chat-kiosk.tsx`),
- registry field labels that encode the ID scheme
  (`services/shared/steps/details.tsx`).

Generic shell strings — "Back", "Processing…", step plumbing sentences —
stay hardcoded English until a translated deployment actually exists;
extracting them buys nothing while every pack ships English. When that day
comes, extend the catalog: `MessageKey` derives from the Malaysia catalog
(`src/packs/malaysia/messages.ts`), so every pack is compile-checked to
cover whatever keys exist.

Other pack-owned text lives beside the catalog rather than in it, keyed by
its consumer: system-prompt variables (`pack.promptVars` — filled into the
`{{country_adjective}}` / `{{id_document}}` / `{{language_instruction}}`
placeholders in `api/_lib/prompts.ts`), the STT repair vocabulary and
examples (`pack.speech`), and the NLU keyword tables (`pack.nlu`).

## Formatting and matching

- `src/lib/format.ts` — money/date/clock rendering reads the `locale:`
  block (`money_locale`, `date_locale`, `clock_locale`, `currency`); every
  default is the value that used to be hardcoded. `plural()`/`countOf()`
  are English morphology — copy in another language writes full phrases
  into its catalog instead of calling them.
- `src/lib/text.ts` — `fold()`/`foldedWords()` normalize with NFKC +
  locale-aware lowercasing and split on Unicode letters, so the
  deterministic option matcher (`ask-match.ts`) and keyword router
  (`flows/nlu.ts`) keep working on accented text. The minimum "distinctive
  word" length is the pack's (`locale.minKeywordWordLength`) — 4 for
  English, 2 for a language with short words like Vietnamese.
- Fonts in `(kiosk)/layout.tsx` load the `latin`, `latin-ext` and
  `vietnamese` subsets. `next/font` requires literal subsets — they cannot
  come from config — so add a script there when a pack needs one.

## What is intentionally still English/Malaysian

The staff enrolment desk, the Payload admin UI, the registry's domain
vocabulary (license classes, race/religion enums, road-tax bands) and the
test suite. See the checklist in [country-packs.md](country-packs.md) for
what a new country actually needs.
